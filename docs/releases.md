# Release procedure

The current published beta is `0.2.0-beta.3`. Dev remains a rolling channel, and each new pre-prod build gets a numbered beta with a signed tag, published GitHub prerelease, changelog and retained binary. Before the next promotion, check existing tags rather than inferring the next number from a package file. A version change alone does not publish a tag, install anything or start a server. Keep an existing tmux workspace independent during beta trials. Never overwrite the executable of a running workspace.

The `v0.2.0-beta.3` tag identifies commit `50a5f02af1721e50dbefbfdef984a40f5c32deed`, the first versioned promotion of the persistent dev channel to pre-prod. Channel selections and immutable build manifests retain the exact commit; the previous pre-prod selection remains available for rollback. Publishing a beta and selecting pre-prod are separate from activation: a running pre-prod server keeps its old shells until an explicitly authorized stop/start. Neither promotion nor activation changes the default tmux environment.

1. Ensure CI is green for the exact release commit, including native PTY/client/UI/tracking/workspace lifecycle tests on Linux x86-64 and ARM64, Rust 1.85, RustSec and license checks, and legacy tmux compatibility tests.
2. Confirm `Cargo.toml`, `Cargo.lock`, README and documentation contain the intended version. Complete the hardware checklist below and describe any unverified device explicitly in release notes.
3. Create a signed `vVERSION` tag and push it when authorized. The tag workflow validates the repository and builds GNU/Linux x86-64 and ARM64 archives and SHA-256 checksum artifacts.
4. Publish the matching GitHub release when authorized. The published-release workflow validates and builds both architectures; a separate publishing job downloads and verifies their checksums before attaching them. Compile/test jobs have read-only repository permissions. Nothing publishes to crates.io, installs a binary or starts a service.
5. Wait for every release-build job to pass before calling the release ready.
6. Verify the archive checksum and unpack into an isolated location. Start a dedicated workspace explicitly, exercise it, detach and reconnect, then stop only that disposable workspace.

A manual `Release build` dispatch validates packaging without creating a tag or publishing a release. Actions artifacts expire after 14 days; attached GitHub release assets remain on the release. Archive names include the package version and GNU/Linux target triple. x86-64 archives build on Ubuntu 22.04 and ARM64 on Ubuntu 24.04. Binaries require compatible glibc; macOS and Windows servers are outside this beta's scope.

Each archive contains the Kelpmux binary, Apache-2.0 license and notice, README, contribution guide, assets, docs, examples, scripts and `dependency-licenses/` with locked versions and upstream license texts for every platform in the lockfile. Cargo fetches all locked sources before offline collection. Rust dependencies retain their own license terms, including the Unicode data license where applicable. Native operation requires no tmux, and archives do not bundle it. Users retaining legacy commands provide their own tmux 3.8+; the checksum-verifying `scripts/build-tmux.sh` remains available for an explicit private build.

## Validation boundaries

Automated PTY profiles cover small and large terminal dimensions, terminal resizing, ANSI colors and Unicode, alternate screens, terminal query replies, fragmented input, paste and mouse events. Tests also cover process survival across reading views and reconnect, controller/observer takeover, safe shrinking around busy jobs, graphical controls, configuration validation, metadata filters and workspace startup/stop behavior. Architecture matrix jobs run real disposable Linux PTYs; these are transport and terminal tests, not proof that every physical client behaves identically.

Before calling a release ready for Joan's daily use, check RootShell on the 11-inch tablet, the MacBook Air 15-inch display and the 32-inch display. Confirm click targets, selection/copy, Alt word editing, paste, Codex and Claude colors, focus, notifications/status changes, reading/fullscreen return, grid picker disabled choices, and resizing while an agent runs. Test detach/reconnect and connection loss with the same pane process identifiers. Record any physical client that has not yet been checked; do not label it verified from automated geometry tests alone.

Release smoke tests use disposable shells, private state paths and explicit shutdown. Detach preserves owned processes while the server stays alive; shutdown ends them. The seven-day journal contains metadata, not process backups, transcripts or automatic agent recovery. No release test modifies user dotfiles or an existing workspace.

## CI cache and parallelism

Quality, native architecture jobs, legacy compatibility jobs, minimum-Rust tests and dependency policy run independently. Stable unit/protocol/hook tests run in quality; stable native integration runs in its architecture matrix. Minimum-Rust coverage deliberately repeats all tests because compiler compatibility is a separate contract. Test fixtures use private sockets and state so independent tests can run concurrently.

Reviewed, pinned official cache actions restore dependency sources and compiled artifacts with OS, architecture, toolchain, lockfile/configuration and job-specific keys. Target caches have commit keys and restore within the same dependency key for incremental builds. PRs restore trusted caches but never save them; only successful push, release and manual-dispatch jobs save caches. No credentials, Cargo configuration, advisory database or audit result is cached. The pinned cargo-audit executable is cached separately; every dependency job fetches current advisories and performs a new audit. The legacy tmux cache is keyed by runner architecture, verified upstream source checksum and build script hash; cached runtime libraries are checked before use. Release builds use separate OS/target-specific caches and always verify generated archives and checksums.
