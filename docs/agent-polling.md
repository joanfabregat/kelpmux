# Agent polling adapters

KelpMux uses one discovery worker and one polling schedule for the native workspace. `discovery::polling::Poller` owns registered Rust adapters. Its shared lifecycle captures one process snapshot, identifies the parent-most interactive agent in each pane, applies explicit links only to matching pane/PID/birth identities, and isolates failed enrichments as unknown observations. The native server rejects stale results after a link changes and reconciles successful observations with the existing journal and hooks. Polling stays off the PTY and client I/O loop.

## Adapter interface

Implement `discovery::polling::Adapter` and register the implementation in `builtins()`, or supply an alternative registry with `Poller::with_adapters`. The first matching adapter owns an observation. `kind()` reports the existing model kind; adding a new agent family also requires extending that model and its presentation labels. `matches()` recognizes an interactive process, `begin_cycle()` resets transient caches, `poll()` enriches an agent from supported metadata, and optional `sessions()` lists explicit linking candidates. Adapters must not start, resume, send input to, or otherwise mutate an agent. An adapter error discards its partial enrichment, leaving process discovery intact. Unknown or unsupported metadata is not evidence of completion. These are compiled adapters rather than dynamically loaded libraries or shell plugins.

The Claude adapter retains its validated live record, explicit resume identity and optional hook integration. The Codex adapter retains supported process identity and bounded structured rollout fallback, and queries the existing local app-server for known thread IDs. Its metadata connection is reused within a cycle, thread summaries are cached, and connection failures stop repeated attempts for that cycle. Requests retain their absolute deadline and byte limits; new metadata requests stop after a 1.2-second cycle budget, with at most 128 cached summaries. Names and status fields are bounded, and transcript/tool content is discarded. Both adapters use the same scheduling, process identity, result handling and UI status path.

## Terminal program status

Codex 0.165.0 and Claude Code 2.1.295+ emit the shared [Program Status Protocol, OSC 7501](https://www.superlogical.com/rex/docs/build/program-status). KelpMux answers its capability query before any subsequent device-attributes reply, allowing Claude to detect support. A bounded incremental parser handles BEL/ST terminators, fragmented sequences, reset/prompt markers, nested record IDs, inherited application identifiers and subtree clearing. Each pane stores at most 256 records. Free-text titles/messages are validated and discarded; they never enter the journal. Protocol IDs are record identifiers, not automatically conversation IDs.

Terminal reports are bound to the pane's foreground process group and birth identity, then to its discovered agent process. Codex and Claude application identifiers select their records; an unrelated application's report does not change agent status. Waiting takes precedence over working among matching child records. Reports remain valid without a heartbeat while the same agent owns the foreground job. Process replacement, backgrounding, full reset and explicit clearing prevent stale activity. Shell-prompt markers drop working/blocked records; completed/error records remain until cleared or replaced. Durable notification history remains independent of live records.

Current terminal evidence takes precedence over daemon/transcript observations and lifecycle hooks. The shared discovery worker persists that evidence without blocking PTY I/O, and stale discovery results cannot overwrite a newer terminal report. Unsupported/older agents retain the existing metadata and hook fallbacks. Terminal reports are application-provided evidence, not an authentication boundary against another process that can write the same PTY.

Codex now launches normally, without an injected `--remote`, a local RPC proxy, daemon startup or a Codex shell function. Its working directory and arguments retain their normal meaning, including when using a shared daemon or `/resume`. Activity works even when the current thread ID is unknown. The former bridge's automatic conversation identity is intentionally no longer claimed.

## Optional conversation metadata

A shared daemon can report thread status without identifying which TUI displays that thread. KelpMux never guesses from a shared directory, a busy thread or the newest transcript. Automatic discovery continues when reliable identity is available. Otherwise, prefix then `i` opens a conversation picker for the active agent tab. Alternatively open the workspace overview with prefix then `o`, select a tab and press `l`. The picker uses read-only `thread/loaded/list` and `thread/read` metadata, with Enter or a row click to link. It never calls `thread/start`, `thread/resume` or `turn/start`.

The first picker row clears an explicit link and restores automatic discovery. A link lives for the current agent process and is invalidated by process exit, replacement or a changed birth identity. A picker opened for an old process cannot bind its replacement. Switching conversations within the same Codex TUI requires relinking if Codex does not expose that change through reliable identity metadata. Links are not saved across server restarts, because native shell processes do not survive those restarts. The daemon endpoint follows the server's configured `CODEX_HOME`, or the user's default `.codex` directory. Listing unavailable metadata shows a retry message without blocking the terminal.

## Notifications and historical tabs

Notification history is retained for seven days, including events from closed tabs and older workspace runs. New events record a run identity and their shell PID. The popup identifies a matching current tab by its displayed number, including parked tabs; unavailable targets are labeled historical. Bell events use the alert symbol rather than an unknown-state question mark. Selecting a historical row acknowledges it without jumping to a different shell. Old history without origin metadata remains readable but is never treated as a verified navigation target. Current tab selection and inline unread indicators use the same origin check.

## Validation

Fixtures cover both built-in adapters, replacement adapters, failed enrichments, reused PIDs, shared-daemon ambiguity, explicit identity conflicts, bounded metadata RPCs, caching and read-only request methods. Real owned-PTY fixtures exercise Codex/Claude terminal status independently, including detection reply ordering and status surviving metadata polling without a conversation link. Parser tests cover fragmentation, bounds, reset/clear, hidden string sequences, hyperlink coexistence and foreground ownership. Shell fixtures check normal Codex arguments/directories and the interactive-only Claude hyperlink override. UI fixtures cover loading, row clicks, keyboard navigation, observers, legacy alert history and reused pane IDs. Tests use private synthetic metadata and sockets, never user transcripts or credentials.

## Idle Claude notifications and Codex transport

The `idle_prompt` lifecycle notification means idle, while `permission_prompt` and explicit permission requests mean input needed. A newly observed idle Claude session's terminal bells are silent until that session has been observed working; explicit approvals remain actionable before its first turn. Bells after work still produce notifications, and a positively identified new session resets the work baseline.

Codex's Unix app-server control socket uses HTTP Upgrade and WebSocket text messages, rather than newline-delimited JSON. KelpMux uses that transport only for read-only metadata requests, with message/frame limits and absolute read/write deadlines even while a frame is incomplete. The adapter requires reliable thread identity before querying a particular thread. Terminal activity needs no such mapping.
