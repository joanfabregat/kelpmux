# Contributing

Use the pinned Rust toolchain, commit `Cargo.lock` and the root `package-lock.json` (one lockfile for the `web` and `web-core` npm workspaces), and keep changes focused. Build and execute code in the container workflow required by your environment. Tests use disposable shells and require no installation or connection to a real workspace; build the server first with `cargo build -p kelpserver --bin kelpserver --locked`, because the lifecycle tests start it from beside the test build of `kelpmux`.

The terminal server (`crates/server`), the protocol crate (`crates/protocol`), the client core (`crates/client`) and the browser terminal layer (`web-core/`, `@kelpcore/web`) are workspace members, so a change to them and to the TUI or web client that consumes it lands in one pull request. Keep `kelpserver` and `kelpclient-protocol` free of client crates and of client presentation or WASM code; their tests must use the server's own types or the protocol crate, and cross-checks that need both sides live in `tests/`. Application presentation (TUI, web layout, relay, navigation) stays in `src/` and `web/`. Protocol changes must update [the stream contract](docs/server/native-client-protocol.md) and say whether they are additive (a new Welcome capability or optional field) or require a version change; a change to `STREAM_PROTOCOL_VERSION`, or to public Rust APIs KelpHub uses, must name the KelpHub changes needed to consume it.

Run formatting, Clippy for all workspace targets with warnings denied and all workspace tests before pushing. Run the explicitly enabled legacy tmux suite when changing that adapter or its shared dependencies. Native PTY, lifecycle and attach tests require Linux and standard shells; legacy integration requires tmux 3.8+. Every fixture owns private sockets and state, cleans up its server, and must be safe alongside another fixture. Agent discovery tests use synthetic `/proc` and metadata files, never real credentials or transcripts.

New discovery support needs fixtures for missing fields, stale PID identity, multiple sessions in one directory, unsupported schemas, ambiguous evidence and session conflicts. Never use terminal output or the latest transcript as an identity guess. Never persist prompts or entire hook payloads. Size and lease changes need real PTY tests proving process identity survives. Grid and reading changes need pure geometry tests plus real PTY tests proving process identity survives and occupied panes cannot be removed. Input changes need fragmented escape/paste tests and an attach fixture proving application keys pass through. Startup changes need reconnect, duplicate instance, explicit stop and independent workspace coverage.

CI runs formatting, Clippy and all workspace tests (KelpMux, the server, the protocol crate and the client core) on Linux x86-64 and ARM64, full Rust 1.89 compatibility, the `kelpclient` WASM build, the browser layer's locked npm install, audit, type check and unit tests, the web client's checks, build and browser tests, RustSec advisories, the dependency license policy and legacy compatibility jobs. Independent fixtures use two test threads; architecture jobs run in parallel. Trusted-event caches reduce rebuilds, but dependency advisories are fetched and checked on every run. Document hardware validation separately from automated terminal profiles.

Dependency additions must be maintained, audited, and compatible with Apache-2.0 distribution. License changes require updating the explicit CI allowlist and collecting the locked source license texts offline. Actions stay pinned to reviewed commits. Cache writes belong only to successful trusted events; do not cache secrets, audit results or mutable advisories. Build/package jobs remain read-only; only the release upload job receives write permission. Release builds are described in [docs/releases.md](docs/releases.md).

For ordinary development, publish to the persistent dev channel after local checks and green CI on the exact commit: register the release executable and defaults with `scripts/channels.sh`, install its manager, then select the full commit ID for dev. Each dev connection replaces an outdated dev server, ending that dev workspace's old shells/jobs; connections to the selected build reuse its server. Preprod remains manual: never promote or restart it without task authorization. Do not overwrite retained executables, and preserve settings across replacement. See `docs/native.md` for commands.

Every preprod promotion must be traceable to a signed beta tag and a published GitHub prerelease for the exact validated commit. Dev remains a rolling channel; cut a new numbered beta for each new preprod build. Determine the next version from existing tags, align the package/lockfile and documentation versions, include all changes since the previous release, and wait for release validation, both Linux packages and checksum verification before declaring the release ready. Keep the previous immutable preprod build for rollback. Staging a promotion does not replace a running server; activation requires authorization to end its shells and jobs. Follow [the release procedure](docs/releases.md).

The legacy demo is separate. When explicitly preparing one, retain its executable under `target/demos/BUILD_ID/kelpmux`. After validation and green CI, atomically update `target/demos/current` to that directory. Never overwrite an executable used by a running workspace. The stable `scripts/demo.sh` command selects a build-specific workspace and preserves its existing settings. Do not start or restart Joan's legacy demo without explicit authorization.

Never start, stop or restart a workspace you did not create for a test. Stopping a workspace ends its shells and jobs.
