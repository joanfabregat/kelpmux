# Contributing

Use the pinned Rust toolchain, commit `Cargo.lock`, and keep changes focused. Build and execute code in the container workflow required by your environment. Tests use disposable shells and require no installation or connection to a real workspace.

Run formatting, Clippy with warnings denied and all ordinary tests before pushing. Run the explicitly enabled legacy tmux suite when changing that adapter or its shared dependencies. Native PTY, lifecycle and attach tests require Linux and standard shells; legacy integration requires tmux 3.8+. Every fixture owns private sockets and state, cleans up its server, and must be safe alongside another fixture. Agent discovery tests use synthetic `/proc` and metadata files, never real credentials or transcripts.

New discovery support needs fixtures for missing fields, stale PID identity, multiple sessions in one directory, unsupported schemas, ambiguous evidence and session conflicts. Never use terminal output or the latest transcript as an identity guess. Never persist prompts or entire hook payloads. Grid and reading changes need pure geometry tests plus real PTY tests proving process identity survives and occupied panes cannot be removed. Input changes need fragmented escape/paste tests and an attach fixture proving application keys pass through. Startup changes need reconnect, duplicate instance, explicit stop and independent workspace coverage.

CI runs native integration on Linux x86-64 and ARM64, with separate formatting/lint/contracts, full Rust 1.85 compatibility, dependency policy and legacy compatibility jobs. Independent fixtures use two test threads; architecture jobs run in parallel. Trusted-event caches reduce rebuilds, but dependency advisories are fetched and checked on every run. Document hardware validation separately from automated terminal profiles.

Dependency additions must be maintained, audited, and compatible with Apache-2.0 distribution. License changes require updating the explicit CI allowlist and collecting the locked source license texts offline. Actions stay pinned to reviewed commits. Cache writes belong only to successful trusted events; do not cache secrets, audit results or mutable advisories. Build/package jobs remain read-only; only the release upload job receives write permission. Release builds are described in [docs/releases.md](docs/releases.md).
