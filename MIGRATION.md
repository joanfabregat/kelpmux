# Repository architecture

KelpMux contains the OSS TUI, the terminals-only web client and the components KelpHub shares with it: the OSS terminal server (KelpServer, `crates/server`), the portable protocol crate (`crates/protocol`), the shared client library (`kelpclient`, `crates/client`) and the browser terminal layer (`@kelpcore/web`, `web-core/`). These lived in the separate [KelpCore](https://github.com/joanfabregat/kelpcore) repository (formerly KelpServer) from the split until they were merged back here ([ADR 0004](docs/adr/0004-kelpcore-merged-into-kelpmux.md)). KelpHub contains the private web application and authenticated management service. The temporary standalone server and client repositories were consolidated into this workspace as internal Cargo crates; there are no operational dependencies on those repositories.

## History and attribution

The original extraction source is the preserved KelpMux development commit `1033e4b`, including the latest local web work rather than the older pre-prod beta. The original checkout and running dev/pre-prod installations are unchanged. The complete original development snapshot is retained privately in KelpHub's `archive/pre-split-development` branch.

The earlier extraction imported path-filtered histories into each component. Those commits preserve original authors, dates and messages and record `Source-Repository` and `Source-Commit`. Filtering changed commit IDs, so the migration operator re-signed those derived commits; those signatures attest to extraction rather than representing the original upstream signatures.

This consolidation imports the complete public server and client main histories using non-squashed subtree merges into `crates/server` and `crates/client`. Their existing commit IDs and signatures remain intact. A subsequent ordinary commit moves the portable protocol package to `crates/protocol` and removes redundant repository policies and lockfiles. A merge commit must retain the subtree ancestry on main; squash-merging this consolidation would discard that ancestry. Subsequent ordinary development can use squash merges.

`crates/server` and `crates/protocol` later moved to the public KelpServer repository, copied from this repository at `eb31da5` and synchronized with the server changes up to `cfe28de`. Their history up to that point remains in this repository's history. KelpMux then removed both directories and depends on KelpServer at a pinned Git revision.

The KelpServer repository was then renamed KelpCore ([KelpCore ADR 0003](docs/adr/core/0003-kelpcore-shared-repository.md)). `crates/client` and the browser terminal layer `web/src/terminal/` (with its unit tests) moved there byte-identical from this repository at `7179aa3`, as KelpCore's `crates/client` and the `@kelpcore/web` package (`web/src/`). Their history up to that point remains in this repository's history. KelpMux then removed both and depends on `kelpclient` at the same pinned KelpCore Git revision as `kelpserver`, and on `@kelpcore/web` at the same KelpCore commit.

KelpCore was later merged back into this repository ([ADR 0004](docs/adr/0004-kelpcore-merged-into-kelpmux.md)): a signed, non-squashed subtree merge imported KelpCore `main` at `5ca7b6d`, with its complete history and signatures, under `core/`, and the following ordinary commit moved its crates to `crates/server`, `crates/protocol` and `crates/client`, its browser layer to `web-core/`, its ADRs to `docs/adr/core/` and its server documentation to `docs/server/`, and merged its policies, CI and lockfiles into this repository's. `git log --follow` and blame trace the moved files through both moves. As with the earlier consolidation, the merge commit must stay on main; squash-merging it would discard KelpCore's ancestry.

Unfiltered original development refs and private web files must never be pushed to this public repository. Preserve LICENSE/NOTICE and third-party attribution. Private repository hosting does not revoke an imported file's license.

## Boundaries and compatibility

KelpServer (`kelpserver`, 0.3 or later) owns PTYs, terminal emulation, sessions, per-pane leases, activity discovery and the pane stream session API; since 0.3 it has no tabs, parking, focus or other UI state, and KelpMux uses its own web relay. Its `kelpclient-protocol` crate contains portable wire types and validation without client-state or WASM dependencies. `kelpclient` provides terminal client state and Rust/WASM bindings, and `@kelpcore/web` the browser terminal layer. The root package contains the TUI, the web client and the legacy tmux adapter. The three crates are members of the root Cargo workspace, declared once in `[workspace.dependencies]` by path, so the server, the TUI and `client-core.wasm` use one protocol crate. Client/server cross-checks that need both sides live in this repository's `tests/`.

The TUI is a client of the pane stream and renders locally (KelpServer ADR 0002 step 2); the composed-screen TUI was removed from KelpMux, and `ctl`, `stop` and the web bridge use the stream session API instead of the composed administration messages (web bridge API version 3). KelpServer 0.3 (ADR 0002 step 3) then removed the composed protocol 58 and all server-side UI: the server speaks only the pane stream, still version 1, and starts every workspace without panes; the TUI or web client creates them (`--startup-panes layout` is gone, `none` is still accepted). KelpServer 0.3 records only `shell` and `cwd` in `workspace.json` and keeps other keys; KelpMux writes its startup `template` and `ui` settings beside them and reads the composed UI's old files (`tab-layout.json`, sidebar preferences) itself for the TUI's one-time migration. `kelpmux benchmark` was removed with the composed frames, and `kelpmux diagnostics` prints the smaller 0.3 report. A running KelpServer 0.2 also speaks stream version 1 and stays usable by this TUI until it is restarted on 0.3. One started with `--startup-panes layout` made its own startup tabs: KelpServer 0.3.0-beta.1's protocol types could not decode its Welcome; since 0.3.0-beta.2 it decodes (`StartupPanes::Layout`) and the TUI adopts those tabs instead of creating its layout beside them. KelpServer 0.3.0-beta.2 (`kelpclient-protocol` 0.3.0) also removed the client presentation it had kept for KelpMux; KelpMux now has its own startup template format (`native::templates`), retained-client selection (`upgrade::attach_matching`), restore choices, vitals glyphs, status labels and glyphs, tmux label escaping, and a TUI tab type that adds its number, parking and colour to the server's `PaneInfo`. Package names and executable names remain unchanged. Existing XDG paths, workspace identities, SSH authentication, ownership and recovery semantics remain unchanged. No runtime state migration, release or deployment is part of the repository split.

KelpHub owns authenticated management, uploads, its browser application and its hosting. KelpMux contains a terminals-only browser client (`web/`, `kelpmux web-bridge`, `kelpmux web-relay`; see [ADR 0003](docs/adr/0003-web-client-in-kelpmux.md)) built on the `@kelpcore/web` terminal layer (`web-core/`), which KelpHub may consume too. KelpHub still builds against its old KelpServer pins; when it resumes, it takes its Rust server dependency, its WASM build (`kelpclient`) and the terminal layer from one commit of this repository. Its web host supplies embedded assets to the public generic relay. The relay contains no KelpHub asset bundle or enrollment API. Workspace and file operations require SSH authentication.

## Build and validation

From this workspace, run `cargo build --workspace --release --locked`, `cargo build -p kelpserver --bin kelpserver --release --locked`, `cargo test --workspace --locked` (after building `kelpserver` for the test profile), formatting, Clippy for all workspace targets and dependency audits in the approved container environment. Build browser bindings with `cargo build -p kelpclient --release --locked --target wasm32-unknown-unknown`. CI also covers Linux x86-64/ARM64, Rust 1.89 (the `kelpmux` MSRV and the toolchain the whole workspace is tested with; the KelpCore crates still declare 1.85), WASM, the browser layer's unit tests and the legacy tmux adapter, and checks that `Cargo.lock` and `package-lock.json` resolve `kelpserver`, `kelpclient-protocol`, `kelpclient` and `@kelpcore/web` to this workspace.

Install `kelpserver` beside `kelpmux`, or set `KELPSERVER_BINARY` explicitly. `kelpmux start` and `ssh-entry` launch the standalone server; `attach` connects without owning its PTY lifetime. Explicit `--server-binary` remains supported. `kelpmux server` remains a compatibility dispatch. For a standalone daemon the client authenticates the live peer and checks protocol compatibility instead of trying to execute the server as a TUI.

KelpHub builds the same client crate to WASM, validates its web assets and embeds them in its executable. KelpHub web hosting and its management `web-bridge` use the KelpHub binary; the KelpMux web client uses `kelpmux web-relay` and `kelpmux web-bridge`. A compatible web-role restart can preserve terminal processes; a terminal-daemon restart ends its shells/jobs. Permanent hosting and beta promotion remain separate tasks.
